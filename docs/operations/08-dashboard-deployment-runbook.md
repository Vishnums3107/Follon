# Dashboard deployment runbook

**Status:** deployable read-only operator surface. This runbook does not close
the PAPER, controlled-live, design-partner, broker-backed options, legal, or
paying-customer acceptance gates.

## What is deployed

The dashboard unifies the implemented market-data, replay, research, PAPER,
controlled-live, operations, options, and commercial evidence views. It reads
immutable artifacts and probes PostgreSQL and MinIO reachability. It does not
submit an order, operate a kill switch, approve a live action, receive a
credential, charge a customer, erase private data, sign a release, or append an
operator ledger.

The boundary is intentional: those actions have stronger independent operator,
four-eyes, secret, confirmation, or offline-signing requirements than a web
dashboard can provide in the current architecture.

## Local verification

From the repository root, with protected local values in `infra/.env`:

```powershell
docker compose --env-file infra/.env -f infra/compose.dev.yml up -d --build
docker compose --env-file infra/.env -f infra/compose.dev.yml ps
Invoke-WebRequest http://127.0.0.1:8080/api/v1/health -UseBasicParsing
Invoke-RestMethod http://127.0.0.1:8080/api/v1/workspaces
```

Every service must report healthy. Open `http://127.0.0.1:8080` and confirm the
dependency cards and all ten tailored primary workspaces: health/gates,
datasets/experiments, strategy identities, backtest comparison, OMS lifecycle,
risk, portfolio/attribution, causal replay/incidents, journals, and
commercial/deployment controls. Also verify the capability/source/documentation
mapping, recursive artifact index, filters, search, structured renderers, and
original-artifact downloads. The host `var/` directory is mounted read-only in
the dashboard container.

Workspace cards open a populated detail panel and update the location to
`#workspace/<workspace-id>`. The server also returns the dashboard shell for
the stable `/workspaces`, `/evidence`, and `/workspace/<workspace-id>` paths;
all dashboard assets use root-relative URLs so direct navigation works.

## Browser troubleshooting

- After rebuilding the dashboard, use `Ctrl+F5` once to replace cached HTML and
  JavaScript.
- A console message naming a `chrome-extension://` URL is generated by that
  browser extension, not by Follon. Verify in an extension-free private window
  or disable that extension for `127.0.0.1`. Do not add `unsafe-inline` to the
  dashboard Content Security Policy to accommodate extension injection.
- `/favicon.ico`, `/favicon.svg`, `/styles.css`, `/dist/main.js`, `/evidence`,
  `/workspaces`, and `/workspace/<workspace-id>` must return HTTP 200. Unknown
  paths such as `/invalid/` intentionally return HTTP 404.

## Authenticated operator deployment

1. Keep the published dashboard address on loopback. Do not change it to
   `0.0.0.0`.
2. Terminate HTTPS in an operator-managed reverse proxy on the same protected
   host or private administrative network. Enforce modern TLS, request limits,
   security headers, and the organization's access logs and alerting policy.
3. Create a high-entropy dashboard password in the approved secret manager and
   materialize it as a protected, single-line host file. Do not place it in the
   repository or `infra/.env`.
4. Set `FOLLON_DASHBOARD_USERNAME` and the absolute
   `FOLLON_DASHBOARD_PASSWORD_FILE` path in a protected environment source.
5. Start the base profile with the secure overlay:

```powershell
docker compose --env-file infra/.env -f infra/compose.dev.yml -f infra/compose.dashboard.secure.yml up -d --build
```

Production mode fails closed when either credential is missing or the password
is shorter than 16 characters. HTTP Basic authentication is only an operator
gate for this bounded deployment. It is not customer identity, role-based
authorization, or entitlement enforcement.

## Security properties to verify

- The port is published only on `127.0.0.1`.
- The container runs as UID 10001 with a read-only root filesystem, all Linux
  capabilities dropped, `no-new-privileges`, a PID limit, and a memory/CPU cap.
- The evidence mount is read-only and no Docker socket, broker credential,
  signing key, customer identity, or database password is mounted.
- Only allowlisted `.json`, `.ndjson`, `.md`, and `.csv` paths beneath the
  evidence root are exposed. Traversal, hidden/tooling directories, and symlink
  escapes are rejected; artifacts over 10 MiB are not indexed or rendered.
- Content is emitted with `nosniff`, no-store caching, frame denial, no referrer,
  and a restrictive Content Security Policy. Markdown is rendered as inert text.
- The Node and Python build/runtime base images are pinned by digest. A release
  candidate still requires SBOM generation, vulnerability review, signature,
  and `follon-admin self-host-readiness` evidence.

## Operational checks

Monitor `/api/v1/health` from the local host and the authenticated
`/api/v1/status` response through the TLS boundary. Alert on container restarts,
unavailable PostgreSQL or MinIO status, repeated authentication failures at the
reverse proxy, unexpected artifact growth, or a changed image digest.

Back up PostgreSQL, MinIO, and evidence according to the approved retention
plan. Test restoration before relying on the dashboard for an operational
session. Keep host patching, encrypted storage, time synchronization, and log
retention under the operator's infrastructure controls.

## Stop conditions

Stop the dashboard and preserve logs if authentication is bypassed, a port is
exposed beyond the intended boundary, a secret appears in an artifact, artifact
validation fails, the expected image digest changes, or a dashboard path is
used to attempt a privileged action. Do not promote the system to capital-bearing
or customer-facing use until the external gates in the implementation status
are independently satisfied.
