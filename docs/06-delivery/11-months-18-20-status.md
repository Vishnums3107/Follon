# Months 18–20 status: commercial controls and self-hosting

This increment supplies deterministic, local control primitives for the commercial
boundary. It does not collect payment cards, replace a payment processor,
authenticate customers, or assert that any customer has paid. Those are external
operating facts which must be evidenced outside the source tree.

## Implemented

- `follon-commercial` provides a process-exclusive, fsynced, SHA-256-chained
  commercial ledger. It accepts only typed tenant-provisioning and externally
  evidenced subscription-observation records; arbitrary events and likely secret
  fields are rejected.
- A provisioned plan plus the latest effective subscription observation derives
  a deterministic entitlement at an explicit UTC instant. `PAID` is full access,
  `GRACE` is read-only, and suspended, cancelled, missing, or expired records
  deny access. Subscription evidence is a pseudonymous external reference plus
  a hash, never a card number, email address, or raw provider payload.
- Versioned privacy/data-inventory inputs use pseudonymous SHA-256 subject
  references. Retention plans hash the exact reviewed file bytes and delete only
  one named file after the caller supplies the exact plan fingerprint. Changed,
  missing, symlinked, held, out-of-root, and audit-evidence privacy candidates
  fail closed.
- Release manifests bind source revision, SBOM digest, exact artifact paths,
  lengths, and hashes. Detached Ed25519 signatures are verified against a
  trusted public key before every artifact is accepted. Canonical JSON prevents
  a second textual representation from acquiring the same operational meaning.
- The hardened self-host configuration requires loopback-only binding and a
  `managed_command` secret-provider boundary, then binds manifest, signature,
  and trusted-key fingerprints. Readiness is emitted only when every pointer,
  signature, and artifact verifies and the verified commercial ledger derives a
  current `FULL` self-host entitlement for that exact tenant.
- `follon-admin` provides the operator workflow. All plans, receipts,
  manifests, signatures, key metadata, and readiness evidence are immutable
  outputs; repeat publication of identical bytes is idempotent and conflicting
  overwrite is refused.
- JSON Schemas, fixtures, unit tests, and a CLI end-to-end test cover the full
  workflow, including a deliberately tampered release artifact.

## Non-negotiable operating boundary

The release key generated by `follon-admin release-keygen` is a PKCS#8 private
key intended for an offline or CI signing environment. It must not be placed in
the repository, a container image, a compose file, an environment variable, or
a customer-hosted server. Production signing should use an operator-managed
HSM/KMS or controlled offline signer which emits the same detached signature
contract. The implementation has no remote signing-service client by design.

Likewise, the commercial ledger is durable evidence, not a payment gateway or
authorization service. The organization operating Follon must independently
verify and retain the provider event/receipt whose digest it records, restrict
who can append ledger records, and enforce the derived entitlement at its
application gateway before offering a hosted service.

## Acceptance gates still external

The milestone is only complete in business terms after either ten paying
professionals or three paying organizations have completed an agreed normal
workflow. That requires contracts, legitimate payment-provider evidence,
support records, consent/legal review, and customer success data. None can be
created or truthfully inferred by this repository.

Before declaring that gate passed, retain an immutable per-customer evidence
packet containing the provision record, provider evidence reference, derived
entitlement, onboarding completion, support/incident outcomes, and explicit
consent to the applicable privacy and retention policy. Audit the packet with
the runbooks below; do not retain customer content in the packet itself.

## Verification

The dedicated commercial workflow is covered by:

```powershell
cargo test -p follon-commercial
cargo test -p follon-cli --test commercial_workflow
```

Run the full repository verification before any release candidate:

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```
